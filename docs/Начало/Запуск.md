# Запуск

Локальный стек: Vite для приложения и Supabase в Docker для базы и входа.

## Первый раз

```bash
npm install
npm run db:start                    # Supabase в Docker, порты 544xx
cp .env.example .env                # подставить ANON_KEY из вывода supabase status
npm run import:anki                 # словарь и озвучка из Anki, см. ниже
npm run dev
```

Приложение поднимется на `http://localhost:5173`, база — на `127.0.0.1:54421`.
Порты выбраны нестандартные, чтобы не конфликтовать с другими проектами
Supabase на той же машине.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | дев-сервер на 5173, только localhost |
| `npm run dev:lan` | то же, но слушает все адреса — для просмотра с телефона |
| `npm run build` | продакшен-сборка |
| `npm run lint` | ESLint (oxlint) |
| `npm run test` | тесты Vitest |
| `npm run typecheck` | проверка типов |
| `npm run db:start` / `db:stop` | поднять и остановить Supabase |
| `npm run db:reset` | пересобрать базу с нуля по миграциям |
| `npm run generate:types:local` | перегенерировать типы из локальной базы |
| `npm run import:anki` | залить словарь и озвучку из запущенного Anki |

Перед коммитом обязательны `lint`, `test` и `typecheck` — так записано
в [AGENTS.md](../../AGENTS.md).

## Словарь

Базу миграции создают пустой. Слова и озвучка живут в коллекции Anki
и попадают в неё скриптом:

```bash
npm run import:anki
```

Нужны: запущенный Anki с дополнением AnkiConnect (порт 8765) и файл
`data/rank-map.csv` — сопоставление колоды с частотным списком. Папка
`data/` в git не входит: репозиторий публичный, а словарь личный.

Заливка повторяемая — гоняйте сколько угодно, слова обновляются, а не
дублируются. Флаги: `--dry-run` считает и ничего не пишет, `--skip-audio`
заливает только слова, `--force-audio` перезаливает звук поверх.

**После `npm run db:reset` заливку надо повторить**, и обязательно вместе
со звуком: сброс пересоздаёт и базу, и бакет хранилища.

## Просмотр с телефона

Телефон должен быть в той же сети, что и компьютер.

```bash
npm run dev:lan
```

Vite напечатает сетевой адрес вида `http://192.168.x.x:5173`. Его и
открывать с телефона.

Адрес Supabase подставляется из адресной строки, отдельной настройки не
нужно: в `.env` он записан как `127.0.0.1`, но с телефона этот адрес
указывал бы на сам телефон, поэтому в дев-режиме хост берётся оттуда же,
откуда открыта страница. Логика в `src/shared/config/resolveSupabaseUrl.ts`,
в продакшене не срабатывает.

Вход через Google с телефона не заработает — подробности и что делать
вместо него в разделе [Вход](../Вход/Вход.md).

## Устройство проекта

Feature-Sliced Design, зависимости идут только вниз:

```
app → pages → widgets → features → entities → shared
```

| Слой | Что внутри |
|---|---|
| `app` | провайдеры, роутер, глобальные стили и токены |
| `pages` | экраны: учить, слова, статистика, вход |
| `widgets` | оборот карточки — общий для «Учить» и «Слов» |
| `features` | вход и защита маршрутов |
| `entities` | слово и повторение: запросы, типы, планировщик FSRS |
| `shared` | разбор немецких форм, клиент Supabase, утилиты |

Вся логика разбора форм лежит в `src/shared/lib/german.ts` и покрыта
тестами. Компоненты только рисуют результат.
