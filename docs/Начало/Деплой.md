# Деплой

Приложение — статика, база и вход — Supabase. Поэтому части две и живут
они в разных местах:

| Что | Где |
|---|---|
| собранный интерфейс | Vercel |
| база, вход, хранилище озвучки | проект Supabase Cloud |

Vercel не держит Postgres, и это не ограничение конкретно его: собранный
Vite — набор файлов, отдавать их может кто угодно. Вся серверная часть
уже написана как база с политиками RLS, и переносить её некуда, кроме
Supabase.

## Порядок

**1. Проект Supabase Cloud.** Завести, затем связать репозиторий и
накатить схему:

```bash
npx supabase link --project-ref <ref-проекта>
npx supabase db push
```

Миграции создадут таблицы, политики, функции и бакет `audio` — всё то же,
что локально.

**2. Google OAuth.** В Google Cloud Console добавить redirect URI
`https://<ref>.supabase.co/auth/v1/callback`, а в настройках проекта
Supabase — адрес сайта и разрешённые адреса возврата с домена Vercel.
Локальные `127.0.0.1` там останутся для разработки.

**3. Vercel.** Подключить репозиторий; сборка и папка описаны
в `vercel.json`. Переменные окружения проекта:

| Переменная | Откуда |
|---|---|
| `VITE_SUPABASE_URL` | адрес проекта Supabase |
| `VITE_SUPABASE_ANON_KEY` | публичный ключ проекта |

Служебный ключ в Vercel **не нужен и не должен туда попадать**: интерфейс
работает от имени вошедшего человека, и все ограничения держатся
политиками RLS.

В `vercel.json` есть правило переписывания всех адресов на `index.html`.
Без него прямое открытие `/words` или обновление страницы вернёт 404:
маршруты живут в браузере, а файла `/words` на диске нет.

**4. Словарь.** Схема приезжает миграциями, а слова и озвучка — нет:
их источник Anki, и в репозитории их нет намеренно. Заливка с машины,
где запущен Anki:

```bash
SUPABASE_URL=https://<ref>.supabase.co \
SUPABASE_SERVICE_ROLE_KEY=<служебный ключ> \
npm run import:anki -- --remote
```

Флаг `--remote` обязателен для любой нелокальной цели. Служебный ключ
обходит все политики доступа, и промахнуться проектом значит переписать
чужой словарь — поэтому одного адреса мало, нужно ещё и подтвердить.

**5. Администратор.** Таблица `admins` намеренно без политик на запись,
из интерфейса туда не попасть. После первого входа — запросом в базе:

```sql
insert into public.admins (user_id)
select id from auth.users where email = 'ваша@почта';
```

Пока этого не сделано, обращения и бэклог никто не разберёт.

## Что учесть до публичного адреса

**Регистрация открыта.** Войти может любой с аккаунтом Google, а
обращения и бэклог — [общие списки](../Общие-списки/Общие-списки.md)
с правом записи. Пока людей единицы, роли администратора хватает, чтобы
вычистить мусор. Для публичного адреса понадобится премодерация или
ограничение по частоте — сейчас их нет.

**Бакет озвучки публичный.** 4178 файлов доступны любому, кто знает
ссылку. Это озвучка словарных форм, ничего личного в ней нет, но решение
стоит принять осознанно: закрыть бакет можно, тогда ссылки придётся
подписывать.

**Прогресс не резервируется.** Отдельной выгрузки `cards` и `reviews`
нет; если она нужна, это отдельная задача.
