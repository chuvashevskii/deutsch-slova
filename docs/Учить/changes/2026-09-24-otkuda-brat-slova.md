# Откуда очередь берёт слова

> **Дата:** 2026-09-24 · **Тип:** функция · **Статус:** реализовано, локально
> **Раздел:** [Учить](../Учить.md)
>
> Продолжение: [«знаю» перестало быть навсегда](2026-09-25-znayu-ne-navsegda.md)

## 1. Просьба

«Добавить функцию наоборот: показывать только те карточки, которые нужно
учить, — например только созданные вручную и выбранные "учить сегодня"».

То есть то же, что умел переключатель «учить только слова вне списка»,
но для других наборов и **с возможностью их сочетать**.

## 2. Почему набор, а не ещё два флага

Три булевых переключателя здесь не работают. «Только безранговые» плюс
«только свои» — это либо пересечение, в котором почти всегда пусто, либо
объединение, и по двум галочкам человек не угадает, что имелось в виду.
Хуже того, он увидел бы отмеченные галочки и пустую очередь.

Поэтому один набор источников, `user_settings.learn_sources`:

| Значение | Что берёт |
|---|---|
| пусто | **вся колода** — как было |
| `rankless` | слова без ранга |
| `own` | заведённые руками (`my-…`) |
| `requested` | отмеченные «учить сегодня» |

Отмеченное **складывается по «или»**: это карманы, из которых берут,
а не сито из нескольких слоёв. На экране так и написано, и выбранное
называется словами: «сейчас: заведённые руками + отмеченные на сегодня».

## 3. Что осталось прежним

**Начатую карточку отбор не выкидывает.** Правило было и раньше
(`or c.reps > 0`), и оно важнее, чем кажется: человек включает режим
на время, а у начатого слова уже идёт срок повторения — исчезнув
из очереди, оно вернулось бы позже, чем нужно.

**`learn_rankless_only` осталась в схеме**, но больше не читается;
прежний выбор перенесён в набор миграцией. Снести колонку сразу нельзя:
фронт выкладывается тем же пушем, что и схема, но приезжает раньше —
[это уже ловили](../../Начало/Залив-разбора.md), — и старая страница
настроек успела бы записать в несуществующую колонку. Удалить следующей
заливкой.

## 4. Чем проверено

### Сценарием на живой базе

Очередь живёт в SQL, и обычные тесты до неё не достают. Между тем она
уже ломалась молча — отдавала плоское слово вместо `{word, card}`,
и экран показывал «на сегодня всё» при тридцати словах в очереди.

Поэтому [`scripts/check-queue.sql`](../../../scripts/check-queue.sql):
строит свой мирок в транзакции — четыре карточки, отметки, настройки —
и откатывает целиком.

```bash
psql "postgresql://postgres:postgres@127.0.0.1:54422/postgres" -f scripts/check-queue.sql
```

| Источники | Ждали | Сошлось |
|---|---|---|
| — | все четыре | ✓ |
| `rankless` | безранговое + своё | ✓ |
| `own` | только своё | ✓ |
| `requested` | только отмеченное | ✓ |
| `own` + `requested` | оба | ✓ |
| все три | три из четырёх | ✓ |
| `own`, но ранговая уже начата | своё **и** начатое | ✓ |

Шестая строка показывает суть: ранговое неотмеченное слово выпало,
а остальные три вошли — по разным причинам, каждое по своей.

### Обычными тестами

- семь случаев на [модель источников](../../../src/entities/settings/model/learnSources.test.ts):
  сложение, порядок, снятие последней галочки, отбрасывание незнакомого
  значения из более новой схемы
- семь на [экран настроек](../../../src/pages/settings/learnSources.test.tsx):
  что именно уходит в базу при каждом нажатии
- 1393 теста, `lint`, `typecheck`, `check-deck`, `check-contract`

## 5. Грабли по дороге

`'rankless' = any (select sources from settings)` не работает: подзапрос
отдаёт одну строку с массивом, и Postgres пытается привести `'rankless'`
к `text[]` — «malformed array literal». Заменено на `@>`. Поймано
при накатывании миграции, а не на живых данных.

## 6. Найдено попутно и исправлено

Кнопка «Завести карточку» в словаре показывалась **всем вошедшим**,
а завести карточку может только админ: отказ даёт функция базы,
на последнем нажатии. То есть человек без прав заполнил бы форму
целиком и получил бы отказ в конце. В бэклоге эта же кнопка была
закрыта правами, в словаре нет — расхождение поймано перед заливкой
в прод.

Теперь кнопка только админу. Ссылка «в бэклог» осталась всем и, когда
она одна, становится главной кнопкой, а не «или ещё вот так».
