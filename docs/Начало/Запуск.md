# Запуск

Локальный стек: Vite для приложения и Supabase в Docker для базы и входа.

## Первый раз

```bash
npm install
npm run db:start                    # Supabase в Docker, порты 544xx
cp .env.example .env                # подставить ANON_KEY из вывода supabase status
npm run import:anki                 # словарь и озвучка из Anki, см. ниже
npm run dev
```

Приложение поднимется на `http://localhost:5173`, база — на `127.0.0.1:54421`.
Порты выбраны нестандартные, чтобы не конфликтовать с другими проектами
Supabase на той же машине.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | дев-сервер на 5173, только localhost |
| `npm run dev:lan` | то же, но слушает все адреса — для просмотра с телефона |
| `npm run build` | продакшен-сборка |
| `npm run lint` | ESLint (oxlint) |
| `npm run test` | тесты Vitest |
| `npm run typecheck` | проверка типов |
| `npm run db:start` / `db:stop` | поднять и остановить Supabase |
| `npm run db:reset` | пересобрать базу с нуля по миграциям |
| `npm run generate:types:local` | перегенерировать типы из локальной базы |
| `npm run import:anki` | залить словарь и озвучку из запущенного Anki |
| `npm run check:deck` | проверить содержимое колоды |
| `npm run check:contract` | сверить форму ответов базы с тем, что ждут экраны |

Перед коммитом обязательны `lint`, `test` и `typecheck` — так записано
в [AGENTS.md](../../AGENTS.md).

Что и чем покрыто, включая сценарии на живой базе, — [Проверки](Проверки.md).

## Словарь

Базу миграции создают пустой. Слова и озвучка живут в коллекции Anki
и попадают в неё скриптом:

```bash
npm run import:anki
```

Нужны: запущенный Anki с дополнением AnkiConnect (порт 8765) и файл
`data/rank-map.csv` — сопоставление колоды с частотным списком. Папка
`data/` в git не входит: репозиторий публичный, а словарь личный.

Заливка повторяемая — гоняйте сколько угодно, слова обновляются, а не
дублируются. Флаги: `--dry-run` считает и ничего не пишет, `--skip-audio`
заливает только слова, `--force-audio` перезаливает звук поверх.

**После `npm run db:reset` заливку надо повторить**, и обязательно вместе
со звуком: сброс пересоздаёт и базу, и бакет хранилища.

### После сброса вся колода становится черновиком

И это не видно по ошибкам — заливка проходит молча, а «Учить» остаётся
пустым.

Отметку «сверено» проставляет миграция
[`20260922240000_draft_cards`](../../supabase/migrations/20260922240000_draft_cards.sql)
одной строкой: `update words set confirmed_at = now()`. Она разовая
и помечает то, что лежит в базе **на момент её накатки**. В первый раз
колода из Anki там уже лежала, и 1462 карточки стали сверенными. После
`db reset` миграции идут по пустой базе, помечать нечего, — и залитая
следом колода приходит черновиками целиком.

Карточки из Anki узнаются по идентификатору: у них это номер заметки,
числовая строка. У черновиков — `list-0042`, у разделённых — хвост `_b`.

```bash
psql "postgresql://postgres:postgres@127.0.0.1:54422/postgres" -c \
  "update public.words set confirmed_at = now() where id ~ '^[0-9]+$' and confirmed_at is null;"
```

Сверять после этого так: черновиков должно остаться столько, сколько
их в `data/drafts/` плюс разделённые карточки, а не вся колода.

Порядок «сначала Anki, потом миграции» повторить нельзя: миграции
создают саму таблицу. Поэтому строка выше — часть восстановления,
а не обходной путь.

## Если локальная заливка звука падает с 42P10

`database error, code: 42P10` при загрузке в хранилище означает, что схема
базы ушла вперёд контейнера Storage: в схеме появились колонки
версионирования и уникальные индексы стали частичными, а контейнер старой
версии по-прежнему шлёт `ON CONFLICT (bucket_id, name)`.

Это расхождение локального стека, не приложения: в облаке те же файлы
заливаются. Лечится обновлением CLI и образов:

```bash
npm i -D supabase@latest
npm run db:stop && npm run db:start
```

До обновления можно заливать словарь без звука: `npm run import:anki -- --skip-audio`.

## Просмотр с телефона

Телефон должен быть в той же сети, что и компьютер.

```bash
npm run dev:lan
```

Vite напечатает сетевой адрес вида `http://192.168.x.x:5173`. Его и
открывать с телефона.

Адрес Supabase подставляется из адресной строки, отдельной настройки не
нужно: в `.env` он записан как `127.0.0.1`, но с телефона этот адрес
указывал бы на сам телефон, поэтому в дев-режиме хост берётся оттуда же,
откуда открыта страница. Логика в `src/shared/config/resolveSupabaseUrl.ts`,
в продакшене не срабатывает.

Вход через Google с телефона не заработает — подробности и что делать
вместо него в разделе [Вход](../Вход/Вход.md).

## Установка на телефон

Приложение ставится на домашний экран: манифест `public/manifest.webmanifest`
и иконки в `public/icons/`. После установки оно открывается на весь экран
без адресной строки — для тренажёра, куда заходят по нескольку раз в день,
это заметная разница.

`theme-color` в `index.html` совпадает с фоном страницы до знака: иначе
полоса статуса остаётся чужого цвета и стык видно.

Иконки сделаны из одного `public/icons/icon.svg` — тёмная бумага, серифная
Z и нижняя перекладина цветом женского рода, как «tausend» в заголовке.
Пересобрать растровые версии, если знак изменится:

```bash
qlmanage -t -s 512 -o /tmp/ico public/icons/icon.svg
```

Знак умещается в центральные 60% холста, поэтому тот же файл годится
и как maskable: Android обрежет его по своей форме, ничего не отрезав.

## Устройство проекта

Feature-Sliced Design, зависимости идут только вниз:

```
app → pages → widgets → features → entities → shared
```

| Слой | Что внутри |
|---|---|
| `app` | провайдеры, роутер, глобальные стили и токены |
| `pages` | экраны: учить, слова, статистика, вход |
| `widgets` | оборот карточки — общий для «Учить» и «Слов» |
| `features` | вход и защита маршрутов |
| `entities` | слово и повторение: запросы, типы, планировщик FSRS |
| `shared` | разбор немецких форм, клиент Supabase, утилиты |

Вся логика разбора форм лежит в `src/shared/lib/german.ts` и покрыта
тестами. Компоненты только рисуют результат.
