# Просмотр с телефона в локальной сети

> **Дата:** 2026-09-21 · **Тип:** функционал · **Статус:** реализовано
> **Раздел:** [Вход](../Вход.md)

## 1. Задача

Открыть дев-сборку с телефона, чтобы смотреть вёрстку на настоящем экране.

## 2. Три преграды

| Преграда | Решение |
|---|---|
| Vite слушал только `127.0.0.1` | команда `npm run dev:lan` |
| Адрес Supabase в `.env` — `127.0.0.1`, с телефона это сам телефон | хост берётся из адресной строки |
| Google не принимает приватные адреса как redirect URI | вход по паролю только в дев-режиме |

Сам Supabase доступен по сети без настройки: Kong уже слушает `0.0.0.0:54421`.

## 3. Подстановка адреса

`src/shared/config/resolveSupabaseUrl.ts` — чистая функция. Если страница
открыта не с `localhost` и не с `127.0.0.1`, а настроенный адрес указывает
на петлевой интерфейс, хост заменяется на тот, откуда открыта страница.
В продакшене и на машине разработчика не срабатывает. Пять тестов.

## 4. Кнопка Google по сети не показывается

Нажатие уводило на `127.0.0.1:54421/auth/v1/authorize`, что с телефона
означает сам телефон, и браузер показывал «сайт недоступен». Починить
нельзя: адрес GoTrue и клиент Google жёстко привязаны к `127.0.0.1`.
Поэтому кнопка убрана, вместо неё объяснение и указание на вход по паролю.
Проверка вынесена в `isLoopbackHost` рядом с `resolveSupabaseUrl`.

## 5. Проверено

Запросом с тем же Origin, что у телефона: preflight на `/auth/v1/signup`
отдаёт `Access-Control-Allow-Origin: *`, регистрация возвращает сессию
сразу, вход по паролю проходит.
