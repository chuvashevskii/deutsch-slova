# Журнал правок и экран сверки

> **Дата:** 2026-09-22 · **Тип:** база, интерфейс, новое · **Статус:** реализовано
> **Раздел:** [Правки](../Правки.md)

## 1. Зачем

Разбор колоды на однозначность ответа трогает и согласованные карточки.
Владелец колоды решил отметку о сверке с них **не снимать** — значит
правка попадает в словарь сразу, минуя просмотр.

Решение разумное: снять отметку с шестисот карточек значило бы вынуть
их из «Учить» до конца разбора. Но у него есть цена — без журнала
человек не узнает, что его карточка изменилась, и не сможет вернуть
прежнее.

## 2. Что сделано

Таблица `word_edits`, представление `word_edits_view` со строкой слова
рядом, функция `revert_word_edit` и страница `/review` на шесть вкладок.

Журнал пишет скрипт служебным ключом, читает — администратор, откатывает
— он же.

## 3. Откат пришлось пускать через флаг

Триггер `guard_word_update` (миграция `20260922240000`) запрещает
вошедшему пользователю менять у слова что-либо кроме отметки о сверке:

```sql
if to_jsonb(new) - 'confirmed_at' <> to_jsonb(old) - 'confirmed_at' then
  raise exception 'Через приложение у слова меняется только отметка о сверке';
end if;
```

Откат обязан это нарушить — он возвращает полю прежнее значение.
`security definer` тут не помогает: `auth.uid()` внутри функции остаётся
тем же, и триггер срабатывает.

Поэтому `revert_word_edit` поднимает `app.word_edit` на время своей
транзакции, а триггер этот флаг признаёт. Снаружи выставить его нельзя:
PostgREST произвольные настройки сессии не передаёт, а значит
и обойти ограничение через обычный запрос не выйдет.

## 4. Проверено опытом, а не рассуждением

| что проверяли | результат |
|---|---|
| не-админ читает журнал | 0 строк |
| админ читает журнал | строки видны |
| админ правит `words` напрямую | отказано триггером |
| не-админ вызывает откат | отказано функцией |
| админ откатывает | значение вернулось, строка помечена |

Плюс живая проверка в браузере: откат из интерфейса убрал строку
из отбора и уменьшил счётчик вкладки с 3 до 2.

## 5. Раздел навигации — только администратору

`ADMIN_SECTIONS` в `src/shared/config/navigation.ts`. Обычному человеку
пункт не показывается **вовсе**, а не ведёт на отказ: пункт, который
всегда отвечает «сюда нельзя», хуже, чем его отсутствие.

Маршрут при этом открыт всем вошедшим — прятать его не за чем, прятать
нечего: страница сама отвечает отказом, а данные закрыты политикой.

## 6. Что осталось хрупким

Раскладка по шести таблицам записана дважды: в `editTable.ts` для экрана
и в `scripts/check-deck.mjs` для отчёта. Разойдись они — числа
разойдутся тоже. Тест `editTable.test.ts` проверяет, что каждая таблица
из списка достижима, но синхронность со скриптом он не ловит.
