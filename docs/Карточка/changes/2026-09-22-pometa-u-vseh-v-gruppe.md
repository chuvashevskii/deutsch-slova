# Нейтральная помета перестала молчать

> **Дата:** 2026-09-22 · **Тип:** интерфейс, исправление · **Статус:** реализовано
> **Раздел:** [Карточка](../Карточка.md)

## 1. Что было видно

Три карточки с переводом «Получать»:

| | `kriegen` | `bekommen` | `erhalten` |
|---|---|---|---|
| чип на лице | разговорный | *ничего* | книжный |

`bekommen` стоял без подписи. Человек видел «Получать» и пустое место
там, где у соседей ярлык, и выбрать не мог.

## 2. Отчего так вышло

`registerLabel` узнавала только две пометы:

```ts
if (lower.includes('umgang')) return 'разговорный';
if (lower.includes('formell')) return 'книжный';
return null;
```

Нейтральная скрывалась намеренно, и рассуждение в комментарии было такое:
нейтральный регистр — состояние по умолчанию, подпись о нём не сообщает
ничего. Для **одиночного** слова это верно: чип «нейтральный» на `Tisch`
— шум.

Ошибка в том, что помета вообще не ставится одиночным словам. В колоде
её несут 18 карточек, и все 18 стоят парами и тройками с общим переводом.
То есть скрывалось ровно то единственное место, где подпись была нужна.

Заодно молчала и любая помета вне списка: `scheißen` размечен `derb`,
и чипа у него не было — не потому что не надо, а потому что слова `derb`
не оказалось в разборе.

## 3. Как теперь

Помета показывается всегда, когда она есть, и берётся как есть — русская
половина строки «umgangssprachlich · разговорный»:

```ts
const russian = register.split('·')[1]?.trim();
if (russian) return russian;
```

Разбор по словарю остался запасным — для базы, до которой не доехала
миграция формата. Но основной путь больше не перечисляет пометы:
перечисление пришлось бы править всякий раз, когда в колоде заведут
новую, а `derb` уже показал, чем это кончается.

Правило записано в [Карточка → Однозначность ответа](../Карточка.md#однозначность-ответа):
если у слова есть сосед по переводу, помету несёт каждый член группы,
включая нейтрального. У одиночного слова она пуста, и чипа нет — поэтому
появление чипа само по себе о слове ничего не выдаёт.

## 4. Что изменилось в данных

Ничего не заполнялось, менялся только формат — миграции
`20260922310000` и `20260922320000`:

| было | стало | карточек |
|---|---|---|
| `umgangssprachlich` | `umgangssprachlich · разговорный` | 24 |
| `derb` | `derb · грубый` | 1 |
| `register = ''` | `NULL` | 1085 |
| `wortart = ''` | `NULL` | 811 |
| пустая строка в 11 необязательных полях | `NULL` | 1110 |

Двуязычная форма — то, как пишет колода из Anki; голый немецкий и пустую
строку приносила заливка черновиков. Различие было незаметно интерфейсу
(`word.komparativ ? … : null` отсекает и пустую строку, и `NULL`)
и поэтому дожило до момента, когда понадобилось спросить «заполнено ли
поле»: пустая строка проходит проверку на `NULL` и молча считается
заполненной. На этом стоит правило о помете у всех в группе, поэтому
расхождение пришлось убрать до разбора, а не после.

Ограничение в базе требует не перечня помет, а формы «немецкое · русское»:
иначе оно ломало бы заливку из Anki каждый раз, когда там заведут
новую помету.
